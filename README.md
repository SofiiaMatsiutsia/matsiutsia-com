# matsiutsia.com — local static mirror

A fully offline, self-contained copy of https://matsiutsia.com. No build step,
no external requests — open it with any static file server (or directly as a
file) and it looks and behaves like the live site.

## How to run

From this folder:

```
python3 -m http.server 8080
```

Then open http://localhost:8080/ in a browser. (Any static server works —
`npx serve`, VS Code's "Live Server", etc. Opening `index.html` directly via
`file://` mostly works too, but a local server is more reliable for the font
`@font-face` rules.)

## Site-wide navigation

All 9 pages share one `<nav class="site-nav">`, pasted in as the first child
of `<body>` (before `#container`), styled by `styles/nav.css`. It's a single
hand-written, **unlayered** stylesheet rather than 3 copies per page — the 5
original pages duplicate their markup once per responsive breakpoint
(`data-width="375"/"800"/"1280"`), but the nav doesn't follow that pattern.
Because the machine-generated CSS on those 5 pages lives inside `@layer`,
this unlayered nav.css always wins layout conflicts without needing to fight
specificity.

- **Desktop/tablet (≥800px)**: single-line bar — name, page links, a
  "Work with me" mailto CTA.
- **Mobile (<800px)**: compact header (name + CTA + hamburger) that opens a
  full-screen overlay with large links and social icons pinned to the
  bottom. Driven by `js/nav.js`; without JS, the overlay/hamburger aren't
  used at all — the links render as a plain static stacked list instead, so
  there's no dead button.
- The 4 case-study pages highlight "Design" (`aria-current="true"`) instead
  of adding themselves as separate nav items.

`about.html`, `design.html`, `talks.html`, and `offerings.html` are new,
hand-written pages (not exported from Figma Sites) — plain, single-markup
responsive HTML styled by `styles/pages.css`, with placeholder copy for the
site owner to fill in. They never load any of the machine-generated
per-page CSS.

## Where to edit things

- **Text**: open the relevant `.html` file and edit the text directly — it's
  plain, real HTML (`<p class="...">Your text</p>`), not a template. Search
  for the copy you want to change.
- **Images**: swap the file in `assets/images/` (keep the same filename) or
  edit the `src="assets/images/..."` attribute in the HTML to point at a new
  file.
- **Colors / spacing / fonts**: each page's look lives in its matching file
  under `styles/` (e.g. `voyage-monitor.html` → `styles/voyage-monitor.css`).
  Classes are utility-style (`css-xxxxxx`), generated by the original design
  tool rather than hand-named — search for the property you want to change
  (e.g. `background-color`, `font-size`) rather than the class name.
- **Site nav**: the same `<nav class="site-nav">` markup is pasted into all
  9 pages (first child of `<body>`); its look lives in `styles/nav.css`,
  hand-named (`site-nav__*`) and easy to search. Adding a 6th top-level page
  means pasting a new `<li>` into that markup on every page.
- **The 4 new pages**: plain hand-written HTML/CSS (`styles/pages.css`), no
  `css-xxxxxx` utility classes — edit the text directly.

## How this was built

The live site is built with **Figma Sites** (Figma's website-publishing
product) — there's no source code to recreate, only Figma's own generated
output. Each page is server-rendered to real HTML/CSS (confirmed by fetching
the pages with plain HTTP, no browser JS involved), then a ~1MB proprietary
runtime hydrates it for animations. This copy keeps the real, rendered
HTML/CSS/fonts/images and drops the proprietary runtime, since that runtime:
- is an unreadable minified bundle (not "editable" in any real sense),
- is tied to Figma's own JSON data format, and
- reports back to `https://www.figma.com` (telemetry) — incompatible with a
  private offline copy.

## Known gaps

- **Entrance animation is approximated, not exact.** The live site fades/slides
  content in via the dropped runtime (built on Framer Motion). This copy adds
  a simple CSS fade-in on `#container` (see `styles/motion.css`) that respects
  `prefers-reduced-motion`. It looks close but isn't the original easing/stagger.
- **Card resting opacity was inconsistent (one card was invisible).** Same
  root cause as above: the export froze each "Selected works" card's preview
  frame mid scroll-reveal, leaving a different leftover inline opacity per
  card — `0.9` on some, unset (fully opaque) on others, and `0` (fully
  invisible) on the Housing Anywhere card. `styles/interactions.css` now
  normalizes all 6 cards to a consistent resting `opacity: 0.9`, which also
  brightens to `1` on hover as part of the card hover/press interaction.
- **The case-study "← Back" button is now a real link** (`<a href="index.html">`,
  3 near-duplicate copies per case-study page, one per responsive breakpoint).
- **The homepage's "Experiments with GenAI" and "Download CV" pills were
  removed** (all 3 breakpoint copies of each). They were inert Figma Sites
  "interaction" elements (`role="link"`, no `href`) with no working
  destination. Both ideas now have a real home: "Experiments with GenAI" as
  the "Experiments" subsection of `design.html`, and outreach generally via
  the new "Work with me" mailto CTA in the site nav. Add a CV file and a
  real link back if/when "Download CV" should return.
- **The 4 new pages (`about.html`, `design.html`, `talks.html`,
  `offerings.html`) are placeholders.** Structure, subnav anchors, and the
  Design page's case-study cards are real; most body copy is
  "Placeholder — ..." text for the site owner to replace.
- **Responsive breakpoints are untouched.** The original CSS ships all three
  breakpoint layouts (desktop ≥1280px, tablet 800–1279px, mobile <800px, plus
  a 600px sub-breakpoint) inline and toggles them with plain `@media` queries
  — nothing was rewritten here, so behavior should carry over exactly. The
  homepage was visually re-verified at 375/800/1280px while building the card
  hover interaction below, with no layout regressions; the case-study pages
  weren't re-checked and are still worth a manual resize pass.
- One data endpoint the live site calls (`/_json/.../_cms/_index.json`)
  already 503s on the live site itself — it wasn't mirrored since it's
  unused/broken there too.
- No third-party trackers/analytics were found or needed removal — all
  requests on the live site were same-origin.

## Verified

- All 5 pages load with **zero external network requests** (only
  `localhost` + inline `data:` URIs).
- No console errors on any page.
- All internal navigation (project cards, "Back" via real links elsewhere,
  footer/social links) works — social links intentionally still point at
  your real profiles (LinkedIn, GitHub, etc.), not local copies.
- Fonts, images, and icons render at full resolution with no 404s.
- Site nav renders once per page (no duplication) at 375/800/1280px on all
  9 pages, with no horizontal scroll and no regressions to existing content.
- Mobile nav overlay: opens/closes via the hamburger, `aria-expanded`
  reflects state, Escape closes and refocuses the button, tapping a link
  closes the overlay before navigating, background scroll locks while open,
  and focus wraps within the overlay while it's open.
- Works with JavaScript disabled: desktop/tablet nav is unaffected; mobile
  falls back to a static stacked list instead of a dead hamburger.
- `prefers-reduced-motion: reduce` removes the nav's entrance fade and the
  hover/press transitions on nav links, pills, and cards.
